# 系统模块开发约束规范

## 1. 目标

本规范用于保证项目中的各子系统具备以下特性：

| 目标 | 说明 |
| --- | --- |
| 低耦合 | 系统之间不直接依赖内部实现 |
| 高内聚 | 每个系统只负责单一核心职责 |
| 可独立扩展 | 可以按系统逐步增加功能 |
| 可独立测试 | 每个系统都能单独验证核心功能 |
| 边界清晰 | 每个系统都明确负责项与不负责项 |
| 可单独启用 | 某个系统未完成时，不阻塞其他系统开发 |
| 可单独替换 | 系统内部实现可重写，但外部协作方式不变 |


## 2 模块程序集拆分要求

每个模块默认拆分为两个程序集

| 程序集 | 说明 |
| --- | --- |
| 主程序集 | 负责承载模块内部运行逻辑与具体实现 |
| 契约程序集 | 负责承载模块对外公开的接口，以及该模块依赖的外部接口 |

命名约束：

- 优先使用 `Main` 与 `Contracts` 组织模块文件夹
- 优先使用 `模块名.Runtime` 与 `模块名.Contracts` 作为程序集名

目录示意：

```text
Unit
├─ Contracts
└─ Main
```
## 3. 依赖原则
| 规则 | 是否推荐 | 说明 |
| --- | --- | --- |
| Main -> 自己的 Contracts | 是 | 这是基础规则 |
| 其他模块 Main -> 目标模块 Contracts | 是 | 跨模块只通过契约通信 |
| Contracts -> Main | 否 | 这是反向依赖，会破坏边界 |
| Main -> 其他模块 Main | 否 | 会造成实现耦合 |
| Contracts -> 其他模块 Contracts | 可少量允许 | 仅限稳定协议依赖，不要滥用 |
